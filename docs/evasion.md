## Checks

Written after the fixes, to test questions they left open; neither a target of the fixes nor held out. Their predictions were committed before they first ran.

| ID | Evasion | Rules | Predicted | Measured | Prediction | Other rules fired | Drops | Agent restarts |
|---|---|---|---|---|---|---|---|---|
| E17 | Read a service account token projected at a custom path | R006 missed | missed | missed | held | – | 0 | 0 |
| E18 | Read the application's service account token through /proc/<pid>/root from a sidecar | R006 detected | detected | detected | held | R028 | 0 | 0 |

1 of 2 detected or visible; 2 of 2 predictions held.

- **E01.** The copy is dash under /tmp/kworker; R001 matches on the name of the binary.
- **E02.** The session lists a directory and reads /etc/hostname with Python calls; nothing is executed.
- **E03.** The link is made when the pod starts; only the read through it, by cat, falls in the window that is judged.
- **E04.** The pod runs without the runtime's default seccomp profile, which may refuse io_uring, so that what is measured is the sensor.
- **E05.** Detected, or ring buffer drops reported by the sensor, both count as the gap being visible.
- **E06.** One thread opens the name in a shared buffer in a loop; another flips the buffer between /etc/shadow and /etc/hostx, which does not exist. The sensor reads the name the kernel resolved, not the buffer.
- **E07.** The pod is privileged with the host's process namespace, which is what an attacker who escaped to the node has. The report gives the agent restart count, which is how the gap shows; the agent has no heartbeat of its own.
- **E08.** The process is python3 -c with 1500 bytes of comment before the code that opens /etc/shadow; the sensor keeps the first 1024 bytes of argv. No shipped rule matches on the command line, so what truncation costs is the evidence in the alert, not the alert.
- **E09.** Held out. busybox is copied to /tmp/.cache/busybox and its sh applet is reached through a two-line script that nc -e runs, so the executed file is a shell that carries neither a shell's path nor a shell's name.
- **E10.** Held out. cat is copied over /usr/bin/passwd in the container's writable layer; R005 lets /usr/bin/passwd read /etc/shadow.
- **E11.** Held out. R004 and the first step of R025 name download tools; here the interpreter fetches the file itself.
- **E12.** Held out. The session lists a directory and reads /etc/hostname with Perl built-ins; Perl forks once for the operator side and executes nothing.
- **E13.** Held out. Python connects out, starts /bin/sh on a pseudo-terminal and copies bytes between the two, so the shell's stdin and stdout are a terminal and not a socket.
- **E14.** Held out. The kernel records the read while the agent is stopped; killing the agent then frees the buffer that holds it. Privileged pod with the host's process namespace, as E07.
- **E15.** Held out. The sensor ignores its own cgroup so that it does not report itself. A privileged pod with the host's process namespace and cgroup tree moves a process into that cgroup and reads the file from there.
- **E16.** Held out. E05 flooded with process starts and caused no drops; connections cost the agent more per event (M10). Six processes connect in a loop to two that accept, and the read happens in the middle. Detected, or drops reported, both count as visible.
- **E17.** Check, written after the fixes. A pod may project its service account token anywhere; this one mounts it at /var/run/app/token. R006 names the token by the standard path prefixes only, so the kernel is never asked to report an open of this file.
- **E18.** Check, written after the fixes. The pod shares one process namespace, so a second container can reach the application's files through /proc/<pid>/root without the path R006 names. Predicted detected: the kernel builds the path of the opened file (bpf_d_path) by walking up its mounts, and from a reader whose root is in another container that walk ends at the application container's root, giving /var/run/secrets/kubernetes.io/serviceaccount/..., which R006 names. If the path comes out otherwise, the read is missed.
