- **E01.** The copy is dash under /tmp/kworker; R001 matches on the name of the binary.
- **E02.** The session lists a directory and reads /etc/hostname with Python calls; nothing is executed.
- **E03.** The link is made when the pod starts; only the read through it, by cat, falls in the window that is judged.
- **E04.** The pod runs without the runtime's default seccomp profile, which may refuse io_uring, so that what is measured is the sensor.
- **E05.** Detected, or ring buffer drops reported by the sensor, both count as the gap being visible.
- **E06.** One thread opens the name in a shared buffer in a loop; another flips the buffer between /etc/shadow and /etc/hostx, which does not exist. The sensor reads the name the kernel resolved, not the buffer.
- **E07.** The pod is privileged with the host's process namespace, which is what an attacker who escaped to the node has. The report gives the agent restart count, which is how the gap shows; the agent has no heartbeat of its own.
- **E08.** The process is python3 -c with 1500 bytes of comment before the code that opens /etc/shadow; the sensor keeps the first 1024 bytes of argv. No shipped rule matches on the command line, so what truncation costs is the evidence in the alert, not the alert.
