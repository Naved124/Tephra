# E01: Reverse shell through a copy of the shell under another name

Predicted (design, section 8): **missed**. Measured: **missed**. Measured results of every run are in [../evasion.md](../evasion.md).

## What was measured

- `/bin/dash` copied to `/tmp/kworker` and run with a TCP socket as stdin and stdout, in a pod with no other process.
- R001 did not fire. Its condition is `process.Image|endswith` a shell name; the exec event's image was `/tmp/kworker`.
- No other rule fired in the namespace.
- A copy is a new file with its own inode, so identity matching of the kind used for the container runtime (`process.runtime`) would not recognise it as a shell either.
- Not yet checked: the raw exec event of `/tmp/kworker` in Loki (whether it carries `stdin_is_socket` and `stdout_is_socket`).

## Why

R001 asks a question about a name: is the binary that runs called `sh`, `bash`, `dash`, `zsh`, `ash` or `ksh`? A name is the one property of a file that its user controls completely. Copying the shell costs one `cp`, needs no privilege in a writable container, and leaves the program's behaviour untouched: dash does not care what it is called. So the rule detects the default form of a reverse shell, not the technique.

The other half of R001, standard input and output being sockets, is a property the attacker cannot shed: a reverse shell is, by definition, an interpreter whose terminal is a network connection. That half was true here as in A01. The rule throws it away because it is joined by AND to the name test.

Identity matching, the method this sensor already uses to recognise the container runtime, does not help. It compares device and inode, and a copy is a new inode. It works for the runtime because there the question is "is this *the* file on the node", whereas here it is "is this *a* shell".

## Proposed fix

Three changes, in order of value:

1. **A behavioural rule beside R001.** Any exec whose stdin and stdout are both sockets, in a container, from a binary that is not the container's main binary, at medium level; R001 stays as the high-level case of a known shell. Few legitimate programs are started with a socket on both ends (inetd-style services are the known case, and are rare in containers). This catches E01 and any other interpreter wired to a socket. It should be measured in the false-positive run before its level is set.
2. **Content identity for interpreters.** Hash the first few kilobytes of every executed file that is new to the agent (cached by device, inode and change time, so each file is hashed once), and compare with the hashes of the shells in the container's own image. A copied shell then has the identity of a shell under any name. Cost: one read per new executable; the M13 change time already tells when a cached hash is stale.
3. **A rule on executing from a writable path** (`/tmp`, `/dev/shm`, the container's writable layer) after the container started, with R025 already covering the case where the file came from a download tool.

The first is cheap and closes this scenario; the second closes the class.
