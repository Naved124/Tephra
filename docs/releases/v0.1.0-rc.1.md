The first release candidate of Tephra under the `tephrasec` organisation. It is for testing: install it on a throwaway cluster, try to get past it, and tell us what you find.

An earlier `v0.1.0` from November 2026 was withdrawn before anyone used it. This release reuses the number; nothing from the old one carries over.

## Install

```sh
helm install tephra oci://ghcr.io/tephrasec/charts/tephra --version 0.1.0-rc.1 \
  -n tephra --create-namespace
```

Requirements: x86-64 nodes with Linux 5.15 or newer, BTF and cgroup v2. Blocking needs BPF LSM (`bpf` in `/sys/kernel/security/lsm`). The images are signed with cosign; the release workflow's summary shows how to verify them.

## What it does

- **Detection:** eBPF programs record programs started, files opened, connections, signals, mounts and ptrace on every node. The agent ties each event to its pod and checks it against 37 rules (MITRE ATT&CK mapped).
- **Enforcement (opt-in, per pod):** with BPF LSM, the kernel refuses what a blocking rule matches, in pods labelled `tephrasec.tech/enforce=true`. Start in dry-run.
- **Against blinding:** a kill or freeze of the agent is recorded in its own buffer and raised as R030 by the next agent. While the agent is down or silent for 12 s, blind mode (on by default) refuses a short list of next moves in pods, such as reading `/etc/shadow`, and raises R038.
- **Under load:** with the buffer half full, repeated opens of a file are counted instead of sent. Two options cut connection cost; the install notes say when to turn them on.

## Measured on Linux 5.15

22 of 22 attack scenarios detected. In E07 and E14 (kill the agent, then read `/etc/shadow`), the read was refused while the sensor was blind and still reported. A 30-minute false-positive run had no high or critical alerts and no drops. Every number links to its run: https://tephrasec.tech/results/

## Breaking: the label

Enforcement is turned on only by `tephrasec.tech/enforce=true`. The old `tephra.dev/enforce` is not honoured.

## Known issues

- #5 A token read can be credited to a deleted pod when a tmpfs device number is reused.
- #6 Some executed files cannot be read for identity through any fallback.
- #7 Blind mode does not yet refuse anything while the agent is alive but its buffer is full (planned).

## Reporting

Use the issue forms: false positive, detection gap, bug. A way to crash, stop or take over the agent goes to a private security advisory, never a public issue.
